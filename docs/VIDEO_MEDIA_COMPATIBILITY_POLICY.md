# 视频素材兼容性与预处理策略（阶段 6 交付物）

对应实现：`src/videowallpaper.cpp`（metaDataChanged 中的分辨率提示、阶段 3 错误处理）；实验依据：`docs/perf/memory-attribution.md`（实验 3.2/3.3）。

## 1. 支持的容器与编码

- **容器**（UI 文件对话框过滤）：mp4 / webm / mkv / avi / mov / wmv；Qt FFmpeg 后端实际可解容器范围更广，以上为推荐集。
- **视频编码**：以硬件解码能力为准。本测试机（RTX 5060）实测 H.264 / HEVC / AV1 均走 d3d11va 硬解（CPU 0.2–0.4%）；VP9 因本地无编码器未取得实测数据（见限制）。
- **音频编码**：AAC 实测无影响；应用默认音量 0 时按策略禁用音频轨。

## 2. 实测资源阶梯（统一编码参数，稳态均值）

| 分辨率 | Private Bytes | GPU 专用+共享 | 建议场景 |
|---|---:|---:|---|
| 720p30 | 289MB | 212MB | 低配机首选 |
| 1080p30/60 | 404 / 401MB | 441 / 420MB | **推荐默认**（帧率对内存无影响） |
| 1440p30 | 595MB | 801MB | 高配机可用 |
| 4K30/60 | 944 / 928MB | 1381 / 1361MB | 高端机；需要接受 ~1GB 级占用 |
| 用户原片 101Mbps 4K60 | 957–1257MB 包络 | ~1600MB | 高码率使池规模再增 ~15% |

| 编码（1080p30） | Private | GPU 合计 | 说明 |
|---|---:|---:|---|
| H.264 | 404MB | 441MB | 兼容性最广，默认推荐 |
| HEVC | 369MB | 373MB | 略省；老设备硬解支持参差 |
| AV1 | 267MB | 330MB | 最省（−34%）；硬解仅 RTX30+/Intel Xe+ 等较新硬件 |

## 3. 策略

### 3.1 普通模式（当前实现）

- 直接播放用户原始视频；优先硬解；**不自动转码、不修改用户文件**。
- 内存主要来自底层解码池（随分辨率线性：固定 ~210MB + ~88MB/百万像素），帧率不改变内存。

### 3.2 高分辨率提示（本阶段新增，`videowallpaper.cpp` metaDataChanged）

- 视频分辨率高于主屏**物理分辨率**（logical×DPR）时，状态栏提示一次（同一分辨率去重）：
  `提示：视频分辨率 W×H 高于主屏物理分辨率，播放内存/显存占用较高（实测约 NMB），可继续使用或更换适配素材`。
- N 为归因阶梯拟合估算（±15%），仅作量级参考；不阻塞、不弹窗、不强制任何操作。

### 3.3 可选预处理（未实现，设计预留）

任务书允许"未来可选"。若未来实现，必须满足：不覆盖原文件；缓存目录可配置且可清理；生成失败回退原视频；不阻塞主界面；不在播放中频繁转码；**默认关闭**。实现载体建议独立离线工具（调用 ffmpeg），不进入壁纸进程。

## 3.5 帧率上限与资源（默认 24 FPS，2026-09-13 实测）

"帧率上限"的实现是 **playbackRate 放慢播放**（高于上限的素材按比例慢放，非丢帧渲染）。4K60 同素材三组对照（150s 稳态，`tools/perf/results/fpscap_*.csv`）：

| 场景 | Private | GPU 专用+共享 | CPU | GPU 利用率 |
|---|---:|---:|---:|---:|
| 原速（跟随视频） | 938MB | 1342MB | 0.50% | 119.6% |
| **上限 24（默认）** | 863MB（-8%） | 1354MB（持平） | **0.19%（-62%）** | **60.1%（-50%）** |
| 上限 30 | 883MB（-6%） | 1350MB（持平） | 0.18% | 73.5%（-39%） |

结论与代价：
- **CPU 与 GPU 占用率显著下降**（解码与呈现按帧率等比减少）；**内存/显存容量仅小幅变化**（帧池按分辨率分配，与归因实验"帧率不影响内存"一致；旧基线 S4 的 -40% 主要来自 101Mbps 高码率源的缓冲差异）。
- **代价：高于 24fps 的素材全部慢动作**——60fps→0.4 倍速、30fps→0.8 倍速；≤24fps 素材无变化。这是有意为之的省资源语义，用户可在 UI"帧率上限"中改回"跟随视频"。
- 默认值 24 存在于：`videowallpaper.h`（成员默认）、`mainwindow.cpp`（下拉默认项 + `video/targetFps` 读取默认）；已保存过设置的用户保持其选择。

## 4. 不默认使用 AV1 的理由（任务书 9.5）

| 风险项 | 说明 |
|---|---|
| 旧显卡/集成显卡 | AV1 硬解需较新硬件（RTX30+/Xe+/RDNA2+）；老设备回退**软解**，4K 下 CPU 飙升、可能卡顿 |
| 虚拟机 / 远程桌面 | 通常无 GPU 硬解，任何编码都可能软解；AV1 软解代价最大 |
| 驱动/后端差异 | d3d11va 行为随驱动差异波动，未做全量硬件矩阵测试 |
| 结论 | H.264 保持默认推荐；AV1/HEVC 作为"省内存可选素材"在提示中说明，由用户选择 |

## 5. 不兼容素材的处理（与阶段 3 联动）

| 情形 | 行为 |
|---|---|
| 文件不存在/损坏/读取失败（ResourceError） | 分类提示 → 有限重试（500ms/1500ms）→ 跳过 |
| 格式不支持（FormatError）/拒绝访问 | 同上 |
| 无视频轨（纯音频） | LoadedMedia 检出 `hasVideo()==false` 且无分辨率元数据 → 不重试直接跳过 |
| 同一曲目累计 2 次轮转失败 | 进入失败名单，不再参与轮换（终止乒乓循环与解码器churn） |
| 全部曲目失败 | 整体停播 + 明确文案（终态，无重试循环） |

## 6. 已知限制

1. VP9 未实测（本地无编码器）；按硬件支持情况预期与 H.264 同级。
2. 软解回退检测未做专项实验（本机所有素材均硬解）；诊断日志（阶段 7）记录元数据与错误，便于后续排查。
3. 超高分辨率/超高码率仅测至 4K60@101Mbps；8K 或多轨超大文件未测。
