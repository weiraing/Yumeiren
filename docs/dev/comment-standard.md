# 虞美人代码注释规范

本规范适用于虞美人（Yumeiren）Qt/C++ 项目的所有源代码。所有新增和修改的代码必须遵守。

> **2026-09-19 修订**：本项目注释由「穷尽解释为什么」改为**极简**风格。原有注释写得
> 过于详尽（注释占总行数 18%，最长单段 29 行），已整体精简。**详细论述移入
> `docs/dev/design-notes-*.md`，源码只留一句结论。**

---

## 一、核心原则

1. **注释只解释「为什么」，绝不重复「做什么」**
2. **能一句话说完的，不写两句**
3. **命名清晰的代码不需要注释** —— `m_name = name;` 不需要 `// 设置名称`
4. **不为显而易见的代码加注释** —— `return true;`、`++index;` 不需要注释
5. **注释必须描述真实行为** —— 禁止猜测，必须验证后写入
6. **不许为了覆盖率或「显得周到」而添加注释**

**默认动作是「不写」。** 写注释前先问：读者看代码能不能自己得出？能，就别写。

---

## 二、该写什么（唯一的标准）

只在这几种情况下写注释，且**尽量一句话**：

| 情形 | 例 |
|------|-----|
| **非直观的原因** | `// 传 GazeOff 时必须复位角度，否则模型僵在歪头姿势` |
| **硬约束 / 顺序要求** | `// 顺序是硬要求：先给窗口非零尺寸，再挂视图` |
| **反直觉的取值** | `// 强档刻意不再往下压(试过 1.3)：会饱和成「卡住了」` |
| **平台坑 / Qt 坑** | `// 必须用 GetAncestor(GA_PARENT) 而非 GetParent()：窗口带 WS_POPUP，后者返回 owner(为空) → 恒 NULL` |
| **状态变量的关键语义** | `// 用户是否主动暂停，而不是播放器因窗口不可见而暂停` |
| **清理 / 释放顺序** | `// 先解除输出窗口与播放器的关联，再销毁播放器` |

---

## 三、明令禁止的注释

| 类型 | 示例 | 处理 |
|------|------|------|
| **历史叙述** | `// 曾有一个 hideWindow()`、`// 原来是 🌸 emoji 占位`、`// 2026-09-17 已删除` | **删掉**（属 commit message） |
| **复述代码** | `// 设置音量为 0` + `setVolume(0);` | **删掉** |
| **函数名已说清** | `// 返回后端支持的表情数` + `expressionCount()` | **删掉** |
| **分组标题排版** | `// —— 交互 ——` 分隔线 | 下面每条已能自明就**删掉** |
| **重复注释** | 头文件声明处与 .cpp 实现处各写一遍 | 保留一处（优先头文件） |
| 无意义注释 | `// 构造函数`、`// 返回结果` | **删掉** |
| 过时注释 | 与代码行为不一致 | 修正或删掉 |
| 情绪化注释 | `// 这里很坑`、`// Qt 又抽风了` | **删掉** |
| 个人信息 | `// 作者：xxx`、`// 2026 年修改` | **删掉** |
| 无效 TODO | `// TODO: later`、`// FIXME: bug` | **删掉** |
| 出处标记 | `// 任务书 §4.1` | **删掉**标记，正文按规则处理 |

## 四、文件级注释

每个 `.h` 与负责独立逻辑的 `.cpp` 顶部加简短说明：**说明文件职责，不超过 3 行。**

```cpp
// 看板娘渲染后端抽象。
//
// 两条绘制路径：软件路径 paint() 直接画进窗口 paintEvent；GPU 路径 render() 渲染进
// 窗口自身的 GL 上下文。选哪条由后端在 usesOpenGL() 里表态。
```

要求：
- **不超过 3 行**
- 复杂论述移入 `docs/dev/design-notes-*.md`（**但不要在注释里写引用** —— `docs/` 不入库）
- 不写作者、创建日期
- 不写「本文件实现了某某功能」这类空泛描述

---

## 五、类级注释

只对**跨模块公共接口、资源管理、状态机、线程、Windows API、第三方 SDK** 的类写。
**不超过 4 行**，说明职责与边界。

```cpp
// 看板娘控制器：拥有窗口与渲染器，窗口只借用渲染器。
// 运行状态由状态机管理，动画仅由统一时钟推进；Live2D 失败时降级为占位后端。
```

普通数据结构（POD、简单 struct）不写类级注释；语义不直观的成员逐行一句话说明。

## 六、函数注释

### 公共接口

函数名已说清意图的不写注释。只在以下情况写**一行**：
- 参数含义不明显
- 返回值有特殊语义
- 有调用顺序 / 线程要求
- 会创建或释放资源

```cpp
// 传 GazeOff 时必须把角度复位，否则模型僵在歪头姿势上。
virtual void setGazeStrength(int strength);
```

**不要**用 `@brief` / `@param` / `@return` 的 Doxygen 排版 —— 本项目不用那套，
一句话说明即可。

### 私有函数

函数名已清晰表达意图时**不写**。只在「非直观实现策略 / 平台特殊处理 / 释放顺序有讲究」时写一行。

---

## 七、复杂逻辑与状态机

状态机分支、资源释放这类「删了就出错」的约束，写一行说明**为什么这个顺序**：

```cpp
// 停止状态下允许重启；启动中重复请求直接忽略，避免重复创建播放器和窗口
if (m_state == State::Starting || m_state == State::Running)
    return;
```

### Windows 平台代码

必须说明 **API 使用原因、窗口层级目的、Explorer 重启 / DPI / HWND 相关限制**。
这类注释是本项目最有价值的部分，**务必保留，但压成一句结论**（推演过程移入 `docs/dev/`）：

```cpp
// 必须用 GetAncestor(GA_PARENT) 而非 GetParent()：窗口带 WS_POPUP，后者返回 owner(为空)
// → 恒 NULL → 每 10 秒无谓重挂一次(壁纸每 11 秒闪一下)
```

## 八、长篇论述的归宿

**凡是超过 3 行的说明，一律移入 `docs/dev/design-notes-*.md`**，源码里不写论文。

> ⚠ **源码注释里不要写「详见 docs/...」的引用**：`.gitignore` 把 `docs/` 整体排除
> （2026-09-18 定案），这些文档不进版本库，写引用等于给团队其他人留死链。
> 归档文档只作为本机参考，注释该怎么写就怎么写，独立自足。
