# 视频壁纸循环播放边界抖动：专项排查与修复分析报告

任务书：`视频壁纸循环播放边界抖动专项排查与修复任务书`。
测试环境：同前（Win11 26200 / 2560×1600@150% / 32 核 / RTX 5060 / Qt 6.10.2 MinGW / FFmpeg 后端 d3d11va）。
取证方法：60fps gdigrab 屏幕捕获（桌面可见的壁纸条带）+ signalstats 逐帧帧差（YDIF）/亮度（YAVG）分析；诊断日志（YUMEIREN_DIAG=1）。

---

## 第一部分：任务书 §3 扫描十项结论（代码事实）

1. **当前循环控制入口**：唯一——`applyLoopPolicy()`（videowallpaper.cpp），单视频+自动循环+非随机时 `setLoops(QMediaPlayer::Infinite)`，多曲目 `setLoops(Once)` + EndOfMedia 推进。**已使用 Qt 原生循环机制**（阶段2/3 早已落地），故按任务书 §4 不重复添加，转入"其他逻辑是否干扰原生循环"的排查。
2. **EndOfMedia 处理流程**：仅多曲目播放时触发 `nextTrack()`；单视频 Infinite 循环下后端回绕**不发出** EndOfMedia（见第四部分取证）。
3. **播放器生命周期**：循环边界无任何对象操作（无 teardown/rebuild/重连）。
4. **媒体源设置次数**：每次会话 1 次（`playIndex`；同源重播仅 `setPosition(0)`，且该路径只用于错误重试，非循环）。
5. **视频输出绑定次数**：创建时 1 次（`setVideoOutput`）。
6. **循环时是否调用 stop()**：否。
7. **循环时是否调用 setPosition()**：否。
8. **循环时是否调用 setSource()**：否。
9. **循环时是否重建播放器**：否（诊断计数器：players=1/0 贯穿长循环）。
10. **最可能导致画面抖动的代码位置**：**应用层不存在**——循环边界处后端不发任何事件、应用无代码执行（第四部分取证）；抖动产生于 Qt FFmpeg 后端内部的回绕 seek（解码器 flush + 重填 + 时钟追赶）。

不存在重复循环控制（无 positionChanged 判结尾、无定时器重启、无延迟重启、无输出清空、无音频重启、无重复 play()）。任务书 §5 要求的"唯一循环控制机制"已满足。

## 第二部分：循环边界取证（任务书 §6）

- 诊断日志证明：约 66 秒 5 个循环周期内，后端发出的事件为 **0**（无 mediaStatusChanged/metaDataChanged/EndOfMedia；所有 setPlaybackRate/setActiveTrack 调用只发生在起播阶段）。
- 新增一次性循环配置日志（Debug）：`setLoops(Infinite) player=xxx widget=xxx source=...`——对象地址 + 绑定 + loops 值一次记录；配合"边界零事件"，等价证明循环时对象地址不变、无 teardown/rebuild/重复连接。
- **结论：应用层在循环边界什么都没做，也没有可做的钩子——抖动只能产生于后端内部。**

## 第三部分：素材对照实验（任务书 §7）

素材（均不覆盖原文件，`build/media/video/`）：
- **A 原始视频**：`凡人修仙传 紫灵.mp4` H.264 3840×2160 60fps CFR 12.5s 750帧 ~101Mbps，AAC 音轨 12.5s（与视频等长）；**PTS 0→12.483 严格单调、无负时间戳、无间隔异常；首帧即 IDR；GOP=0.5s**——编码与时间戳完全健康（任务书 §9 检查项全部通过）。
- **B 无音频重封装**：`-c:v copy -an`，不重编码。
- **C 标准化转码**：1920×1080 30fps H.264（libopenh264 8M）。
- **D 循环友好版**：A 重编码 + 首帧克隆 3 帧（0.05s）垫尾。

60fps 屏幕捕获两轮（每轮 36s ≈ 2-3 个边界），尖峰判定 YDIF>20（正常运动 P95≈0.7）：

| 素材 | 第1轮尖峰(处/边界) | 第2轮尖峰 | 形态 |
|---|---|---|---|
| A 原始(含音轨) | 1/2（YDIF 37） | 1/2（37） | 停帧→跳变 |
| B 无音轨重封装 | 1/2（37） | — | 同 A |
| C 标准化 1080p30 | 0/2 | 1/2（36） | 同 A |
| D 首帧尾垫 | 2/2（36-37） | 1/2（38） | 同 A |

**对照推断（按任务书 §7 结果表）**：
- A=B → **音频轨道/音视频时长无关**；
- 四种素材都抖、且单素材逐轮不稳定（C 第1轮 0 处、第2轮 1 处）→ **非素材编码/时间戳问题，是间歇性的播放管线边界行为**；
- 手动循环 vs 原生循环：项目已是原生循环（旧手工循环的黑帧问题在阶段2/3 已消除）。

## 第四部分：伪影形态与首尾内容分析（任务书 §8）

- **伪影指纹**（A 尖峰前后逐帧）：`…0.16, 0.08, 0.00, 0.00, [37.27, 37.19], 0.19…`——即**末帧定格约 33ms（2 个捕获帧 YDIF=0）→ 一帧强跳变（37）→ 恢复正常**。无黑帧（YAVG 全程 >100）、无长时间停滞。
- 机制推断：后端回绕 seek 后重新填充呈现队列期间时钟继续走，恢复时为追时钟**丢弃新循环开头若干帧**，造成"末帧多停 1 帧 + 新循环跳帧"的组合，视觉即"短暂停顿 + 不自然切换"；是否丢帧取决于 refill 完成时刻与 vsync 的竞争，故**间歇性（两轮合计约 30–50% 边界）**。
- **首尾内容连续性（素材 A）**：首帧 vs 末帧（750 帧的第 1/第 750）缩放至 480×270 逐像素平均绝对差 **1.3/255**（最大 36，无 >30 差异像素）——该素材是**内容级无缝循环**，首尾不连续类别（任务书分类 D）**排除**。

## 第五部分：修复尝试与效果（任务书 §10）

| 措施 | 级别 | 结果 |
|---|---|---|
| 原生 `setLoops(Infinite)`（已存在） | P0 | 消除了旧手工循环的黑帧间隙；残余 1 帧级跳变为后端内部行为 |
| 清理重复循环控制 | P0 | 扫描确认本就没有重复控制，无需改动 |
| 首帧尾垫（`tools/make_loop_clip.ps1`） | P2 | **对 1080p30 测试片有效**（帧差尖峰 2→0）；**对 4K60 素材 A 无效**（D 仍每边界尖峰）——因 4K60 的接缝是"停帧+追赶跳帧"，垫片无法掩盖追赶丢帧。**修正上一轮"彻底消除"的结论：该缓解仅在轻量素材上观测有效** |
| 循环配置/边界取证日志 | P2 | 已加（Debug 级，仅诊断模式；不逐帧打印） |

按任务书 §10 禁令：未改动 FFmpeg 参数/D3D11VA/RHI/解码线程/帧缓存/纹理策略；未重写渲染链路。

## 第六部分：长时间循环回归（任务书 §11）

- **30 分钟连续循环浸泡**（素材 A 原片 4K60 101Mbps，`loop_soak30min.csv`）：约 **147 次回绕**，无崩溃、无挂起中断（GPU 全程 >800MB）、句柄 ~3021 / 线程 ~96 稳定、应用层播放器计数 1/0 不变。
- **新发现（与本专项正交但重要）**：该素材长循环出现**台阶式内存扩张**——Private 均值 1377MB [966~2048]，分段斜率：前 10min **-0.2**/min（平稳）→ 中 10min **+74.4**/min（快速爬升）→ 后 10min **+2.2**/min（趋平至 ~2GB）；GPU 专用显存同步扩张（同速）。应用层计数/句柄/线程全程不变、1080p30 同法 48 循环斜率 +0.03/min——指向**驱动/后端解码表面池的延迟动态扩容**，而非应用层泄漏；30 分钟窗口内未见回落后无法确认 ~2GB 即上限。
- **给用户的具体建议**：4K60 高码率素材长期做壁纸时内存会爬到 ~2GB 平台；在意者可改用 1080p 素材（同法实测零增长），或接受该平台值。此发现与循环边界抖动相互独立。
- **自动化回归套件**：7 用例（基础播放/39 次连续换曲/停止重载/全坏停播/跳过/无视频轨/空闲）——结果见 `docs/VIDEO_WALLPAPER_REGRESSION_TESTS.md`，重跑保持 7/7。
- 循环中暂停恢复/切换视频/音量调整：由套件 T03/T05 与状态机心跳覆盖；锁屏/睡眠/Explorer 重启/双屏为人工清单项（机制与已验证路径同源，见 VIDEO_WALLPAPER_SYSTEM_EVENTS.md）。

## 最终结论（任务书 §12 分类）

> **F. Qt Multimedia / FFmpeg 后端呈现边界问题。**

依据链：应用层边界零事件（§第二部分）→ 素材编码/时间戳/首尾内容全部健康（§第三、四部分）→ 音频无关（A=B）→ 标准化与垫片素材同样复现（间歇性 30–50% 边界）→ 伪影形态为"末帧停 ~33ms + 跳帧"（后端 refill 追时钟丢帧的指纹）。排除 A（循环控制）、B（生命周期）、C（异步竞争——应用层无边界回调）、D（首尾不连续）、E（时间戳/编码）。

## 已知限制与后续建议

1. 后端回绕跳变无法在应用层消除；推荐**关注 Qt 6.10.2 之后的版本更新**（社区报告 6.5.3 起媒体结束清空缓冲的行为变化，后续版本可能改进循环回绕），升级后用本报告的 60fps 捕获方法复测即可（脚本与判定标准齐备）。
2. `make_loop_clip.ps1` 对轻量素材有效、对 4K60 无效——工具保留但文档已如实标注适用范围。
3. 切换后端（WMF/GStreamer）与双播放器接力因任务书约束与内存代价不予采用。
4. 若用户对特定素材的接缝零容忍：内容侧把素材剪成"边界帧完全一致且时长对齐到帧"（A 已近乎如此）并接受 ~1/3 概率的 33ms 微跳，或等待后端改进。
