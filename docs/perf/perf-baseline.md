# 视频壁纸模块性能基线（重构前 / Phase 2）

- 测量对象：`build/YumeirenTest.exe`（与 `Yumeiren.exe` 同源码，仅去掉管理员清单以便自动化），构建于重构前 HEAD（`d0cbbb0`，Ninja 构建 no-work-to-do 校验通过）。
- 测量环境：Windows 11（build 26200）zh-CN，单屏 2560×1600 @150% DPI，CPU 32 逻辑核，AMD Radeon 610M + RTX 5060 Laptop，Qt 6.10.2 MinGW（Qt Multimedia FFmpeg 后端，确认 d3d11va 硬解可用）。
- 方法：场景由 `tools/perf/run_scenario.ps1` 通过 HKCU QSettings 播放列表 + 自动恢复路径启动播放；`tools/perf/sample.ps1` 每 5s 采样：CPU%（TotalProcessorTime 增量 ÷ 32 核，同任务管理器口径）、Working Set、Private Bytes（提交）、GPU 引擎利用率（该 PID 全引擎求和，多引擎可 >100%）、GPU 专用内存（Local Usage）、句柄/线程数。原始 CSV 见 `tools/perf/results/`。
- 素材：用户提供 4K60 片源（3840×2160 H.264 60fps 12.5s 101Mbps），另用 ffmpeg 派生 1080p30 / 1080p60（10s）与 5 个 5s 切换短片（见 `build/media/video/perf/`）。

## 关键读数与说明

1. **CPU 表现优秀（硬解生效）**：1080p30 ≈ 0.4%（约单核 5%），4K60 仅 0.75%。日志确认 `d3d11va/dxva2` 可用，解码在 GPU。空闲 0%——无忙循环，1s 策略轮询开销不可测。
2. **内存特征**：播放 1080p 稳定在 ~415MB Private + ~230MB 显存；4K60 达 **1.5–1.8GB Private + ~1.4GB 显存**（Qt FFmpeg 后端帧池，数值波动但 5 min 无单调增长）。这是框架固有成本，重构只能从减少拷贝/池配置入手。
3. **无泄漏**：5 min 浸泡与 34 次连续切换（含解码器重建路径）Private/句柄/线程/显存均零增长；线程数从 112 缓降至 ~100 后稳定（FFmpeg 内部线程收敛，正常）。
4. **S4 实证"帧率上限"的真实语义**：`targetFps=30` 对 60fps 视频是 playbackRate=0.5 **慢动作**——CPU 不变（解码照跑），显存约省 40%（1.4GB→0.8GB）、Private 约省 40%。它不是"降帧渲染"。
5. **S0 复现工作集修剪**：30s 回收定时器把 WS 从 107MB 修剪到 1–4MB，Private 不变（50MB）——证实审计 E2"任务管理器友好型伪优化"。播放中 10s 短片会在 EndOfMedia 边界撞上 30s 定时器把活跃缓冲换出（S1 首轮观察到播放期 WS 被压到 6MB），存在轻微卡顿风险。
6. **S6 实证新 bug（确定性）**：`isForegroundFullscreen()`（videowallpaper.cpp:35-38）将 `GetWindowRect` 的**物理像素**矩形与 `QScreen::geometry()` 的**逻辑像素**比较；本机 150% 缩放下 2560×1600 ≠ 1707×1067，全屏检测**永不命中**，"全屏自动暂停"在高 DPI 系统上完全失效。代码与运行双重证实，归入 P0。
7. **启动→出画**：首个采样点（进程启动后 9.2s）已在满速播放，扣除 4s 初始化等待，实际 ≤5s。精确到帧级需打点，未测。

## 无法测量项及原因

| 场景/指标 | 原因 |
|---|---|
| 多显示器播放 | 本机单显示器 |
| 锁屏 / 显示器关闭 / 休眠唤醒 | 需改变系统全局状态，侵入用户会话，未自动化 |
| Explorer 重启恢复 | 需重启 shell，侵入性强，建议留待功能验证阶段手动测试 |
| 暂停/恢复 ×100 | `VideoWallpaper::pauseResume()` 无任何 UI/外部入口（死代码），外部无法驱动——本身即为 A 类问题 |
| 平均 FPS / 帧时间 | 未装 PresentMon；Qt 未暴露呈现节拍，需重构阶段加打点 |
| 切换耗时（精确 ms） | 无打点日志，仅能从 S5 包络确认切换期间无资源积压 |
| 播放静态图片 | 图片背景走 ExplorerBgTool.dll 注入 explorer 的链路，与本模块无关，不在视频基线范围 |

## 测试期间顺带实证的审计结论

- A1（错误静默）：测试脚本一度把非法路径写入播放列表 → 应用**无任何提示**地静默失败（状态栏保持旧文本），复现 A1。
- 退出清理：每个场景结束均正常关闭进程，8+ 次启动/退出循环中壁纸窗口无残留（teardown 路径工作正常）。
